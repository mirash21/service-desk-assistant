## 📋 Выявленные проблемы

Согласно анализу в Admin Panel (страница Analytics):

1. **36 чанков слишком длинные** (>600 символов) - необходимо разделить
2. **5 чанков короткие** (<200 символов) - необходимо объединить или расширить  
3. **Только 64% документов имеют категории** - необходимо добавить категории при добавлении документов

## ✅ Созданные решения

### 1. Скрипты для автоматического исправления

Созданы следующие скрипты в папке `scripts/`:

#### 🔍 `comprehensive_rag_analysis.py` - Комплексный анализатор
Полный анализ качества базы знаний с генерацией отчета и оценкой 0-100.

```bash
# Анализ образца (100 документов)
python3 scripts/comprehensive_rag_analysis.py

# Полный анализ всех документов
python3 scripts/comprehensive_rag_analysis.py --full
```

#### 📏 `optimize_chunk_lengths.py` - Оптимизация длин чанков
Разделяет длинные чанки (>600) и объединяет короткие (<200).

```bash
# Тестовый режим (показывает что будет сделано)
python3 scripts/optimize_chunk_lengths.py

# Применение изменений
python3 scripts/optimize_chunk_lengths.py --apply
```

**Как работает:**
- Длинные чанки разбивает на части по ~400 символов с перекрытием 50 символов
- Короткие чанки одной категории объединяет в один
- Сохраняет metadata и keywords при модификации

#### 🏷️ `add_categories_to_documents.py` - Добавление категорий
Автоматически определяет и добавляет категории для документов без категории.

```bash
# Тестовый режим
python3 scripts/add_categories_to_documents.py

# Применение изменений
python3 scripts/add_categories_to_documents.py --apply
```

**Поддерживаемые категории:**
printers, network, email, password, software, hardware, security, windows, office, crm, mobile

#### 🔑 `add_keywords_to_metadata.py` - Добавление keywords
*(Уже существовал)* Автоматически извлекает keywords из содержимого.

```bash
python3 scripts/add_keywords_to_metadata.py --apply
```

## ⚠️ Важные предупреждения

### Перед запуском с `--apply`:

1. **Сделайте резервную копию базы данных**
   ```bash
   # Через Supabase Dashboard или CLI
   supabase db dump -f backup_$(date +%Y%m%d).sql
   ```

2. **Всегда сначала запускайте без `--apply`**
   - Это тестовый режим (DRY RUN)
   - Показывает что будет сделано без реальных изменений
   - Проверьте результаты перед применением

3. **Изменения необратимы**
   - После применения откатить сложно
   - Удаленные/измененные документы нельзя восстановить без бэкапа

4. **Ожидайте изменения количества документов**
   - Разделение длинных чанков → больше документов
   - Объединение коротких → меньше документов
   - Это нормально

## 🔧 Технические детали

### Алгоритм разделения длинных чанков

```
Исходный чанк (1000 символов):
"В: Как настроить принтер? О: Подключите принтер к сети. 
 Установите драйверы. Настройте параметры печати. 
 Перезагрузите компьютер."

↓ Разделение с target_size=400, overlap=50

Чанк 1 (400 симв.): "В: Как настроить принтер? О: Подключите принтер к сети. 
                     Установите драйверы."

Чанк 2 (400 симв.): "Установите драйверы. Настройте параметры печати. 
                     Перезагрузите..."

Чанк 3 (250 симв.): "...Перезагрузите компьютер."
```

**Преимущества overlap:**
- Каждое предложение входит в 2 чанка
- Сохраняется контекст
- Улучшается точность поиска

### Алгоритм определения категорий

```python
# Для каждой категории есть список keywords
CATEGORY_KEYWORDS = {
    'printers': ['принтер', 'печать', 'driver', 'драйвер', ...],
    'network': ['сеть', 'wi-fi', 'wifi', 'internet', ...],
    ...
}

# Алгоритм:
1. Подсчитать сколько keywords каждой категории найдено в тексте
2. Выбрать категорию с максимальным количеством совпадений
3. Если совпадений нет → оставить 'unknown'
```

**Пример:**
```
Текст: "Принтер не печатает. Установите driver."

printers: найдено 3 keywords (принтер, печать, driver)
network: найдено 0 keywords
software: найдено 1 keyword (driver)

→ Категория: 'printers'
```

## 💡 Рекомендации для будущих обновлений

### При добавлении новых документов:

1. **Всегда указывайте category в metadata**
   ```python
   metadata = {
       'category': 'printers',  # ← Обязательно!
       'keywords': ['принтер', 'печать'],
       'type': 'faq'
   }
   ```

2. **Используйте оптимальный размер чанка**
   ```python
   chunk_size = 400  # Не 1000!
   overlap = 50      # Для сохранения контекста
   ```

3. **Добавляйте синонимы в текст**
   ```
   ❌ Было: "Введите пароль"
   ✅ Стало: "Введите пароль (password, пин-код)"
   ```

4. **Проверяйте формат Q&A**
   ```
   В: [вопрос пользователя]
   О: [ответ с решением]
      • Шаг 1
      • Шаг 2
   ```

### Для улучшения поиска:

- Регулярно анализируйте unanswered questions

## 🐛 Решение проблем

### Ошибка подключения к базе данных

```
Error: Could not connect to Supabase
```

**Решение:**
1. Проверьте файл `.env`
2. Убедитесь что `SUPABASE_URL` и `SUPABASE_KEY` правильные
3. Проверьте подключение к интернету

### Категории не определяются

**Решение:**
1. Текст может быть слишком короткий
2. Добавьте keywords в `CATEGORY_KEYWORDS` в `utils/document_validator.py`
3. Установите категорию вручную через Admin Panel

### Ошибки при обновлении документов

**Решение:**
1. Проверьте права доступа service role key
2. Убедитесь что таблица `documents` доступна
3. Проверьте логи Supabase Dashboard
