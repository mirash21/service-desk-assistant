# Инструкция по настройке раздела «Деятельность» (Activities)

## Обзор

Раздел «Деятельность» позволяет администраторам просматривать историю диалогов между пользователями и ботом, организованную по пользователям. Эта функция помогает отслеживать активность пользователей, анализировать качество ответов бота и выявлять проблемы.

## Шаг 1: Применение миграции базы данных

### Вариант A: Через Supabase Dashboard (Рекомендуется)

1. Откройте [Supabase Dashboard](https://app.supabase.com)
2. Выберите ваш проект
3. Перейдите в раздел **SQL Editor** (в левом меню)
4. Нажмите **New query**
5. Скопируйте содержимое файла `migrations/002_create_chat_history.sql`
6. Вставьте SQL код в редактор
7. Нажмите **Run** или `Ctrl+Enter`
8. Убедитесь, что выполнение прошло успешно (зеленая галочка)

### Вариант B: Через скрипт автоматизации

```bash
cd /home/mirash/service-desk-assistant
python3 scripts/apply_chat_history_migration.py
```

**Примечание:** Для этого варианта требуется настроить `DATABASE_URL` в файле `.env`.

## Шаг 2: Проверка создания таблицы

После применения миграции убедитесь, что таблица создана:

1. В Supabase Dashboard перейдите в **Table Editor**
2. Найдите таблицу `chat_history`
3. Проверьте наличие следующих колонок:
   - `id` (bigint, primary key)
   - `user_id` (text)
   - `message_type` (text) - значения: 'user' или 'bot'
   - `content` (text)
   - `metadata` (jsonb)
   - `created_at` (timestamp)

## Функциональность раздела

### Основные возможности

#### 1. Просмотр всех пользователей
- Отображение общей статистики по всем пользователям
- Количество сообщений от каждого пользователя
- Разделение на сообщения пользователя и ответы бота

#### 2. Фильтрация по пользователю
- Выбор конкретного пользователя из выпадающего списка
- Просмотр полной истории диалога с выбранным пользователем
- Хронологическое отображение сообщений

#### 3. Фильтры
- **По периоду:**
  - За всё время
  - Сегодня
  - Последние 7 дней
  - Последние 30 дней

- **По типу сообщений:**
  - От пользователя
  - Ответ бота
  - Оба типа

#### 4. Индикаторы типов сообщений
- 🖼️ - Сообщение содержит изображение
- 🎤 - Голосовое сообщение
- ⚙️ - Команда бота
- 🎫 - Создана заявка

#### 5. Метаданные
- Для каждого сообщения можно просмотреть дополнительные метаданные
- Информация о наличии вложений
- Режим работы бота при ответе
- Другие технические детали

#### 6. Пагинация
- Постраничный просмотр сообщений
- Навигация вперед/назад
- Настройка количества сообщений на странице

## Структура данных

### Таблица chat_history

```sql
CREATE TABLE chat_history (
  id BIGSERIAL PRIMARY KEY,
  user_id TEXT NOT NULL,
  message_type TEXT NOT NULL CHECK (message_type IN ('user', 'bot')),
  content TEXT NOT NULL,
  metadata JSONB DEFAULT '{}'::jsonb,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### Примеры метаданных

**Для сообщений с изображениями:**
```json
{
  "has_image": true,
  "image_text": "Распознанный текст",
  "image_description": "Описание изображения"
}
```

**Для голосовых сообщений:**
```json
{
  "has_voice": true,
  "voice_type": "audio_attachment"
}
```

**Для ответов бота:**
```json
{
  "has_voice": false,
  "ticket_created": true,
  "mode": "rag"
}
```

## API методы

Новые методы добавлены в `admin_panel/api/rag_api.py`:

### `get_chat_history(user_id=None, page=1, page_size=50)`
Возвращает историю чатов с пагинацией. Если `user_id` не указан, возвращает все сообщения.

### `get_unique_users()`
Возвращает список уникальных ID пользователей из истории чатов.

### `get_user_stats()`
Возвращает статистику по каждому пользователю (количество сообщений, разделение по типам).

## Автоматическое сохранение истории

История чатов автоматически сохраняется при обработке сообщений в `handlers/message_handler.py`:

- ✅ Текстовые сообщения пользователей
- ✅ Голосовые сообщения (после распознавания речи)
- ✅ Изображения (с распознанным текстом и описанием)
- ✅ Команды бота
- ✅ Ответы бота (все типы)

## Устранение неполадок

### Проблема: Таблица chat_history не найдена

**Решение:**
1. Убедитесь, что миграция применена корректно
2. Проверьте права доступа к базе данных
3. Повторно выполните SQL скрипт из `migrations/002_create_chat_history.sql`

### Проблема: Нет данных в разделе Activities

**Решение:**
1. Убедитесь, что бот запущен и обрабатывает сообщения
2. Отправьте несколько тестовых сообщений боту
3. Проверьте логи на наличие ошибок сохранения истории
4. Убедитесь, что `SUPABASE_URL` и `SUPABASE_KEY` настроены правильно

### Проблема: Ошибка подключения к Supabase

**Решение:**
1. Проверьте файл `.env` в корне проекта
2. Убедитесь, что переменные `SUPABASE_URL` и `SUPABASE_KEY` заполнены
3. Проверьте доступность Supabase API

## Безопасность

- Таблица `chat_history` использует стандартные политики RLS (Row Level Security) Supabase
- Доступ к данным осуществляется через сервисный ключ из `.env`
- Рекомендуется ограничить доступ к панели администратора через базовую аутентификацию
