# Исправление логики обработки сообщений

## Проблема

Бот некорректно обрабатывал входящие сообщения, автоматически преобразуя любой ввод (включая обычные вопросы и команды) в задачи, вместо того чтобы выполнять запрошенные действия или отвечать на вопросы.

## Причина

В функции `_handle_content` отсутствовала классификация намерений пользователя. Все текстовые сообщения проходили через один пайплайн создания задачи через `build_analysis_prompt`, независимо от типа запроса.

## Решение

### 1. Добавлена классификация намерений (`_classify_intent`)

Метод анализирует текст сообщения и определяет тип намерения:

**Ключевые слова для создания задачи:**
- "создай задачу", "создать задачу"
- "зарегистрируй инцидент", "зарегистрировать инцидент"
- "открой тикет", "открыть тикет"
- "заявка", "инцидент", "проблема"
- "не работает", "сломалось", "ошибка", "баг", "поломка", "авария"

**Ключевые слова для вопросов:**
- "как", "что", "где", "когда", "почему", "зачем"
- "сколько", "какой", "который"
- "можешь", "можно ли"
- "объясни", "расскажи", "подскажи", "помоги понять"
- Наличие вопросительного знака "?"

### 2. Реализована условная логика обработки

```python
intent = await self._classify_intent(full_context)

if intent == "question":
    # Обычный вопрос - даем прямой ответ
    return await self._handle_question(full_context, chat_id, user_id)
elif intent == "ticket_creation":
    # Запрос на создание задачи - создаем заявку
    return await self._create_ticket(full_context, chat_id, user_id, mode)
else:
    # По умолчанию создаем задачу (для обратной совместимости)
    return await self._create_ticket(full_context, chat_id, user_id, mode)
```

### 3. Новый метод `_handle_question`

Обрабатывает обычные вопросы без создания задачи:
- Отправляет контекст в Yandex GPT с инструкцией просто ответить на вопрос
- Не создает JSON-структуру заявки
- Возвращает краткий понятный ответ (2-4 предложения)
- Если вопрос требует технической поддержки, предлагает создать задачу

### 4. Выделен метод `_create_ticket`

Инкапсулирует логику создания задачи:
- Использует `build_analysis_prompt` для генерации JSON заявки
- Генерирует ответ пользователю через `build_user_reply_prompt`
- Поддерживает голосовой режим (TTS)

### 5. Обновлен промпт `build_analysis_prompt`

Добавлено предупреждение:
```
ВНИМАНИЕ: Этот промпт используется ТОЛЬКО когда пользователь явно просит 
создать задачу/инцидент/заявку. Если это обычный вопрос или команда - 
этот промпт не должен использоваться.
```

## Примеры использования

### Вопрос (не создает задачу)
```
Пользователь: "Как подключить принтер?"
Бот: "Для подключения принтера перейдите в Настройки → Устройства → Принтеры и нажмите 'Добавить принтер'. Если возникнут сложности, создайте задачу командой 'создай задачу'."
```

### Создание задачи (создает заявку)
```
Пользователь: "Создай задачу, не работает принтер"
Бот: "Спасибо за обращение! Зарегистрирована заявка: 'Не работает принтер'. Приоритет: средний. Ожидайте решения в течение 4 часов."
```

### Команда (обрабатывается отдельно)
```
Пользователь: "/mode rag"
Бот: "✓ Режим переключен на: rag"
```

## Файлы изменены

1. **handlers/message_handler.py**
   - Добавлен `_classify_intent()` - классификация намерений
   - Добавлен `_handle_question()` - обработка вопросов
   - Добавлен `_create_ticket()` - создание задач
   - Обновлен `_handle_content()` - условная логика

2. **utils/prompt_builder.py**
   - Обновлен `build_analysis_prompt()` - добавлено предупреждение

## Тестирование

### Сценарий 1: Обычный вопрос
```bash
# Отправьте боту сообщение:
"Как сбросить пароль?"

# Ожидаемый результат:
# - В логах: "Классифицированное намерение: question"
# - Бот отвечает текстом без создания задачи
```

### Сценарий 2: Создание задачи
```bash
# Отправьте боту сообщение:
"Создай задачу, не работает интернет"

# Ожидаемый результат:
# - В логах: "Классифицированное намерение: ticket_creation"
# - Бот создает заявку и отправляет подтверждение
```

### Сценарий 3: Сообщение с ошибкой
```bash
# Отправьте боту сообщение:
"У меня ошибка при входе в систему"

# Ожидаемый результат:
# - В логах: "Классифицированное намерение: ticket_creation" (ключевое слово "ошибка")
# - Бот создает заявку
```

## Обратная совместимость

По умолчанию (если намерение не определено) бот создает задачу, что сохраняет обратную совместимость с существующим поведением.
